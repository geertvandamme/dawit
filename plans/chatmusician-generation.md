## Goal
Offer a local ChatMusician profile for generating an editable melody over a clip's chords and for trying chords against an existing melody. The user hears and checks a take before putting notes or proposed chords into the song.

## Decisions for you
1. **Scope:** Support clips of any bar length. Answer: all lengths of bars; generate successive context-sized chunks and stitch them in order, including a final partial bar where needed.
2. **Harmonisation:** Include a trial but expose it as supported only if the real-model gate below passes; otherwise leave it disabled with a reason and keep this issue open. Answer: agreed.
3. **Notation:** Support a deliberately bounded single-voice ABC subset, reject repeats and additional voices, and do not silently discard unsupported musical syntax. Answer: agreed.

## What the user does and sees
In the piano roll's Generate panel, choose ChatMusician and an installed Ollama model or type an alias. Choose Melody or Harmonise, then Generate for the selected clip; melody requires a chord for each bar, harmonisation requires a monophonic melody within the clip. Generate consecutive chunks for any clip length, with the final chunk trimmed to the exact clip end; pass the preceding musical phrase as context when it fits. Report chunk progress and make no partial take available if any chunk fails or is cancelled. The panel shows the range, key, 4/4 and chords or source melody, progress, Cancel, errors and take choices. A preview plays the chosen result without modifying the clip or chord track; Stop ends it. Apply notes inserts or replaces notes as chosen, preserving the instrument. In harmonisation, show proposed chord names bar by bar and separately offer Apply chords; do not change existing chords without explicit confirmation. Both actions are undoable together or individually, and a failed or cancelled request changes nothing. Explain unavailable models, unsupported notation and context limits in plain language, with tooltips for all controls. Remember profile and model alias in app settings, never song data.

## Data and saving
Only applied ordinary MIDI notes and explicitly accepted chord-map changes are saved by existing project serialization; no new project format or version. Old projects load unchanged. Pending takes, preview and source ABC are transient. Test saving, loading and MIDI export after application. Capture edit generation and clip identity, and reject stale takes if the project, target, source notes or relevant chords changed while generating or previewing.

## Code
Follow recipes *Topics in an existing guide*, *A long job* and *Checking in the real app*. A ChatMusician request snapshots clip-relative notes, range, key and chord map on the message thread. A profile uses Ollama's streaming `/api/generate` raw prompt, without JSON `format`; keep the current chat/schema path unchanged. Use the model card's `Human: … </s> Assistant: ` template, with explicit ABC output and task-specific musical context. Split arbitrarily long clips into sequential chunks of at most four bars within a conservative context budget; stitch validated results with beat offsets, trim the final chunk at the clip end, and retain the preceding phrase as context when it fits. Fail the whole take on overflow or truncated replies. Establish the actual budget and model metadata in the real-model gate, never assume alias means a particular model.

An ABC parser yields timed pitches and chord labels separately. Require one tune, `M:4/4`, supported major or natural-minor `K:`, explicit `L:`, one voice, valid bar lengths and exactly the requested chunk. Support notes, rests, octave marks, rational durations, key and bar-scoped accidentals, ties and simple and explicit tuplets; reject repeats, alternative endings, multi-voice notation, unsupported key changes, broken rhythm, grace notes, decorations, inline chords and unknown constructs with a location and remedy. Parse bounded input with rational time, validate MIDI pitch 0–127 and note lengths before conversion; no partial results on errors. Chord symbols are labels, never melody notes. Accept only chord forms DawIt's chord model can represent and bar-aligned changes; reject ambiguous or unsupported chords rather than changing them. For harmonisation, serialize the source melody in the supported ABC subset, parse proposed symbols and use `gen::voiceChord` to produce auditionable MIDI voicings, keeping chord-map application separate.

Generation and parsing run off the message thread with cancellable streaming; callbacks use safe lifetime and request IDs. Preview uses an isolated audition path, not the edit; stop it on cancel, target change, transport takeover or destruction. Apply on the message thread under the engine lock, revalidate snapshots and notify notes changed; use a transaction that restores precisely the affected notes and chords, without overwriting subsequent edits. The existing GeneratePanel take handling auto-applies and its local undo assumes ownership of changed chords, so reuse requires a separate staged path and careful conflict tests, not an assumption that preview already exists.

## Theory
**Facts:** (1) ABC expresses notes as text and can label chords; a label is not itself a played accompaniment (exact; [ABC 2.1](https://abcnotation.com/wiki/abc%3Astandard%3Av2.1)). (2) A crotchet lasts one beat in DawIt's 4/4 timeline; four bars span 16 beats (exact; derived 4 × 4). (3) A tie joins adjacent notes of the same pitch into one sustained note (exact; ABC 2.1). (4) A triplet of three quavers takes the time of two, or one beat (exact; ABC 2.1 and 3 × ½ × ⅔ = 1). (5) Model output is a suggestion, not a promise that a melody or harmony fits (opinion).

**Topic text — ABC and generated music.** Summary: Read a text tune and hear it in your song. Explanation: “ABC is a way to write music using ordinary text. C D E G can describe four notes; a chord name such as C above them labels the harmony. The chord name is not an extra note being played. DawIt turns a supported tune into MIDI notes that you can edit in the piano roll. Listen to a take before applying it: a generated tune is a suggestion, and you can change any note. Harmonise proposes chord names for your melody; preview the sound and choose whether to put those chords on the chord track.” Picture: C4, D4, E4, G4, each one beat, over the C label. Tooltips: “Preview: listen without changing the song.” “Apply notes: put this take in the selected clip.” “Apply chords: put the proposed chords on the chord track.” “Cancel: stop the request without applying it.”

**Your song:** with a valid staged take show “This take has N notes. Listen, then apply it if you like.” If it includes proposed chords append “It proposes N chord changes; review them before applying.” With no staged take show “Generate a take to see it here.” No musical quality judgement. Picture notes are MIDI 60, 62, 64, 67 at beats 0, 1, 2, 3, length 1; chord label C. Tests: these values exact; triplet positions 0, 1/3, 2/3 and lengths 1/3 beat, tolerance 1e-9.
